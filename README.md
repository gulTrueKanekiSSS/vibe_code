# Studyspace

Личная учебная система для студента, который изучает технические предметы на английском: понятные объяснения на русском → практика → понимание своих слабых тем → прогресс.

## Возможности

- 5 предметов, 10 модулей, 56 коротких уроков с английскими терминами, примерами и типичными ошибками.
- Формулы KaTeX, безопасный Markdown с подсветкой C-кода, поиск предметов, тем, формул и терминов.
- 64 заранее подготовленных задания: число, краткий ответ, один/несколько вариантов, верно/неверно, последовательность шагов, вывод C, исправление фрагмента C и концептуальный ответ.
- Практика дня, быстрые сессии, слабые темы, выбор предмета/темы, смешанный экзамен без подсказок и промежуточной оценки.
- Четыре уровня подсказок, серверная проверка, XP, mastery, Practice GPA, серия занятий, достижения и история.
- Telegram OIDC, приватные по умолчанию профили, рейтинг за неделю/месяц/всё время.
- Адаптивный интерфейс, светлая/тёмная темы, клавиатурная навигация, `Cmd/Ctrl + K` для поиска.

**AI Tutor V1:** контекстная панель урока/раздела/упражнения, приватная история и объяснения по материалам курса. Требует отдельной серверной AI-конфигурации; без неё показывает понятное состояние недоступности. AI не генерирует оцениваемые задания, не меняет XP/mastery/GPA и не выполняет пользовательский код.

## Быстрый запуск

Нужны Node.js **22.13+**, npm и Docker Compose (либо PostgreSQL 14+).

```sh
npm ci
cp .env.example .env
docker compose up -d db
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev
```

Открой http://localhost:3000 и нажми **«Войти в демо-аккаунт»**. Это отдельный локальный аккаунт; учебные материалы настоящие, начальный прогресс нулевой. Состояние сохраняется в PostgreSQL. Повторный seed обновляет контент, сохраняя пользователей и прогресс.

Контейнер публикует PostgreSQL только на `127.0.0.1:5433`; порт 5432 оставлен другим локальным приложениям. `docker compose stop` останавливает базу, сохраняя её том.

В текущем рабочем окружении установлен локальный Node.js в `node_modules/.bin/node`. Если системный Node старый, после установки зависимостей можно использовать `export PATH="$PWD/node_modules/.bin:$PATH"`. Для чистой установки на другой машине сначала установи поддерживаемую версию Node.

## Переменные окружения

| Переменная               | Назначение                                                                                                |
| ------------------------ | --------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`           | Подключение Prisma к PostgreSQL. В Compose: `postgresql://study:study@localhost:5433/study?schema=public` |
| `NEXT_PUBLIC_APP_URL`    | Полный origin без завершающего `/`: локально `http://localhost:3000`, в production — HTTPS URL            |
| `TELEGRAM_CLIENT_ID`     | Client ID из BotFather                                                                                    |
| `TELEGRAM_CLIENT_SECRET` | Серверный Client Secret из BotFather                                                                      |
| `DEV_AUTH`               | `true` разрешает локальный вход **только при `NODE_ENV=development`**                                     |

`.env` исключён из Git. Значения Compose — только локальные реквизиты; в production нужны отдельные секреты и управляемая база. Основная учебная система работает без AI-ключей; для Tutor см. раздел ниже.

## Telegram

Используется [официальный Telegram OpenID Connect Authorization Code Flow](https://core.telegram.org/bots/telegram-login) с PKCE S256.

1. Создай бота в BotFather. В разделе Login Widget зарегистрируй origin приложения и точный callback: `https://your-domain.example/api/auth/telegram/callback`.
2. Сохрани Client ID и Client Secret в окружении сервера.
3. Установи `NEXT_PUBLIC_APP_URL` на зарегистрированный адрес.
4. Запусти приложение и выбери вход через Telegram.

Сервер создаёт одноразовый challenge, связывает его с HttpOnly SameSite cookie и проверяет state. Код обменивается на токен сервером с PKCE. `jose` проверяет подпись по JWKS Telegram, алгоритм, issuer, audience, expiration и обязательные claims. Только после проверки обновляется пользователь. Сессия — случайный токен; в базе хранится SHA-256, cookie HttpOnly, в production также Secure. Logout удаляет серверную сессию.

Настоящий вход Telegram требует реквизитов и зарегистрированного домена. Без них проверяются локальный вход и отказ в обработке некорректного callback.

## Архитектура

```text
content/subjects.json    Предметы и названия модулей
content/lessons/         Уроки в .mdx с метаданными в начале файла
content/questions/       Задания .json рядом с уроками по предметам
prisma/schema.prisma     Связи, уникальные ключи, индексы
prisma/migrations/       Воспроизводимые SQL-миграции и CHECK-ограничения
prisma/seed.ts           Идемпотентная загрузка материалов
src/app/(app)/           Защищённые страницы Next.js App Router
src/app/api/             Проверка входа, практики, настроек и прочтения
src/components/          Интерфейс, Markdown, формы практики
src/lib/learning.ts      Чистые алгоритмы и конфиг правил
src/lib/content-source.ts Чтение и проверка файлов контента
src/lib/content-service.ts Доступ страниц к контенту через БД
src/lib/practice-service.ts Транзакции, ответы и подсказки
src/lib/progress.ts      Производные показатели и публичный рейтинг
src/lib/auth.ts          Сессии, проверка origin и guards
tests/                   Быстрые тесты алгоритмов и контента
integration/             Тесты на настоящей PostgreSQL
e2e/                     Пользовательские сценарии в браузере
```

Данные организованы как Subject → Module → Topic → Question/Formula. Topic.content содержит разделы урока. PracticeSession содержит PracticeItem; каждая отправка хранится в PracticeAttempt. TopicProgress фиксирует начало и первое прочтение. Показатели XP, mastery, GPA, серии и достижения вычисляются из фактов, поэтому отсутствуют дублирующие счётчики, способные рассинхронизироваться. Настройки приватности вынесены в UserSettings. TutorConversation/TutorMessage/TutorUsage и производный LectureChunk не участвуют в оценивании.

Ответы, нераскрытые подсказки и решения не передаются в клиентский компонент. Авторизация каждой записи выполняется сервером. Запросы мутаций проверяют origin и формат через Zod. Markdown не исполняет HTML/JavaScript, KaTeX работает без trust. Пользовательский код никогда не запускается.

## AI Tutor: настройка и границы V1

Серверные переменные (никаких `NEXT_PUBLIC_*`):

| Переменная | Назначение |
| --- | --- |
| `TUTOR_PROVIDER` | `openai` — первый адаптер; приложение зависит от интерфейса `TutorProvider` |
| `OPENAI_API_KEY` | Серверный ключ проекта провайдера, никогда не отправляется браузеру |
| `TUTOR_MODEL` | Доступная вашему проекту модель Responses API со strict structured outputs |
| `TUTOR_EMBEDDING_MODEL` | Доступная embedding-модель, float vectors до 4096 измерений |

Модели задаются явно, без скрытых defaults. Используется REST [Responses / structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses) и [Embeddings](https://developers.openai.com/api/reference/resources/embeddings/methods/create). После изменения env перезапусти сервер. Ограничь бюджет проекта у провайдера.

После применения миграций и публикации материалов:

```sh
npm run tutor:index
# Только с credentials: внешние embedding-вызовы могут тарифицироваться.
npm run tutor:index -- --embeddings
# Переиндексация одной изменённой темы:
npm run tutor:index -- --embeddings --topic=projection
```

Первая команда не обращается к AI: создаёт текстовый индекс опубликованных Topic.content.sections. Вторая добавляет embeddings; повторный запуск переиспользует неизменённые векторы той же модели. Изменение lesson text/metadata инвалидирует прежний chunk; удаляются только устаревшие производные chunks выбранной темы. После каждого seed, меняющего уроки, обновляй индекс. PDF преобразуются извне в существующие MDX, без нового загрузчика или переписывания страниц. `quizAnswer`, question answers, hidden hints и grading maps не индексируются.

Текущий PostgreSQL не предоставляет pgvector: V1 хранит float arrays в существующей БД и ранжирует cosine similarity не более 64 chunks текущей темы + 192 того же предмета. Тема/раздел имеют приоритет; чужие предметы не подмешиваются. При отсутствии/ошибке embeddings используется lexical fallback, помеченный в результате retrieval. Нет свежего материала — Tutor сообщает о недостатке данных. В контекст попадает до четырёх chunks / 7 KB текста. Для роста библиотеки нужен benchmark и оценка pgvector. Ссылки формируются сервером только по найденным source IDs; PDF page отсутствует, пока у источника нет реальных страниц.

Tutor открывается из урока, раздела, текущего упражнения и разбора завершённой практики. Показывает предмет/тему, сохраняет разговор после reload; quick actions: «Объясни проще», «Дай подсказку», «Почему это так?», «Проверь моё понимание». Системные правила требуют короткое русское объяснение, один диагностический вопрос и продолжение по ответу. Педагогическое качество требует оценки на выбранной реальной модели: test doubles этого не доказывают.

Защита практики:

- До разрешённого раскрытия решения модель выбирает только coaching action; сервер показывает проверенный вопрос или уже открытую подсказку. Это ограниченное сопровождение, **не свободный AI-разбор скрытого решения**.
- После завершения задания/сессии либо открытия четвёртой подсказки (когда обычная практика уже допускает решение) доступно свободное объяснение; по умолчанию оно направляет, а не выдаёт итог сразу.
- Любая незавершённая exam/delayed-feedback/no-hints сессия блокирует Tutor и его историю **во всех контекстах пользователя**, включая уроки. Заверши такую сессию для возвращения к Tutor. Проверка повторяется после ответа провайдера.
- AI не пишет в PracticeAttempt, XP, mastery или GPA. Auth/ownership/origin/body validation выполняются сервером.

История приватна: до 200 разговоров, до 120 сообщений в разговоре; модель получает только последние 12 сообщений / 9 KB UTF-8. Автоматического summary или student knowledge state пока нет. «Новый разговор» после подтверждения удаляет историю текущего контекста, не квоты. PostgreSQL ограничивает запросы до 30/час и 150/сутки на пользователя, включая ошибки провайдера. Одинаковый requestKey не создаёт повторный turn; lease ограничивает зависшие операции. DB-транзакция не держится во время AI-вызова.

Сообщения, недавний диалог и нужные учебные excerpts/безопасный exercise context отправляются внешнему провайдеру. Telegram-профиль, токены входа, ключи и чужая история не отправляются. Не вводи личные данные или секреты. Responses использует `store: false`; это не обещание отсутствия иных retention-политик провайдера. Ответ возвращается только после валидации, без raw token streaming. Ошибки не раскрывают provider payload/credentials. Для публичного запуска нужны ingress limits, мониторинг расходов и политика хранения/удаления данных.

Live-проверка владельцем: настроить env → миграция/seed при необходимости → индекс с embeddings → перезапуск → вход → урок/раздел → вопрос и ответ на диагностический вопрос → sources и reload истории → guided exercise и блокировка Exam. Автотесты используют doubles для AI; полноценная live-проверка без credentials не заявляется.

## XP и mastery

Константы находятся в `src/lib/learning.ts`.

**XP:** EASY 10, MEDIUM 20, HARD 30, CHALLENGE 50. Множители попыток: 1 / 0.8 / 0.6. Подсказки: 1 / 0.9 / 0.8 / 0.65 / 0.4; применяется самый высокий использованный уровень. Результат округляется вниз. Время решения не влияет на награду. После трёх неверных попыток показывается решение и вопрос закрывается.

XP начисляется только за первое успешное решение конкретного вопроса пользователем. Повторная практика обновляет оценку понимания, но не XP. Все изменения практики сериализуются блокировкой строки пользователя в транзакции PostgreSQL. Уникальный submissionKey дополнительно защищает повторную доставку запроса. CHECK-ограничения не позволяют отрицательный XP, некорректное число попыток или награду за неуспешный ответ.

**Mastery:** берётся последний завершённый результат для каждого уникального вопроса темы, максимум 20 вопросов. Вес по давности результата в этой последовательности — `0.9^i`. Успешный ответ оценивается произведением качества попытки, коэффициента подсказки и сложности (0.65 / 0.85 / 1 / 1); неверный — нулём. Средняя оценка умножается на покрытие `min(1, 0.4 + 0.2 × число разных вопросов)` и на 100. Значение ограничивается 0–100. Новая ошибка заменяет прежний успех по тому же вопросу; повторение одного лёгкого вопроса не увеличивает покрытие. Mastery не падает просто из-за медленного обучения.

Overall mastery — среднее только по темам с завершённой оцениваемой практикой. Непрочитанные и только прочитанные темы не становятся нулями; до первой практики вместо оценки показывается «Нет оценки». **Practice GPA** вычисляется из overall mastery по порогам спецификации (95–100 → 4.0, 40–49 → 1.0, ниже 40 → 0.0). Это не официальный университетский GPA. Состояние PRACTICED требует 3 разных успешно решённых оцениваемых задания по теме.

## Рекомендации, серия и рейтинг

- Daily Practice: детерминированный выбор до 5 заданий: до 2 слабых тем, 1 недавно изученная, 1 для интервального повторения (последняя практика была 14+ дней назад), затем смешанные задания. При недостатке данных набор дополняется автоматически. При равенстве используется стабильный хеш даты и вопроса. Сначала выбираются разные темы. У пользователя только одна daily-сессия на дату, повторный запуск возобновляет её.
- Слабые темы: только оценённые темы с ошибками и mastery ниже 70%, отсортированные по mastery и недавним ошибкам. Простой просмотр или чтение тему слабой не делает.
- Экзамен: 15 вопросов вперемешку из 5 предметов; подсказок, промежуточной правильности и XP нет до последнего ответа. После завершения показываются общий результат и разбивка по темам.
- Своя практика: на странице `/practice` можно выбрать предмет, несколько тем, уровни EASY/MEDIUM/HARD/CHALLENGE, доступные для выбранных тем типы вопросов и 1–20 заданий. Редактируемые пресеты задают уровень, количество, подсказки и момент показа обратной связи. Интерфейс показывает доступное количество и не запускает сессию с недостаточным набором. Сервер повторно проверяет фильтры, распределяет вопросы между сложностями и темами, предпочитает невиденные и ранее ошибочно решённые вопросы и сохраняет конфигурацию вместе с порядком заданий. Повторный запрос с тем же ключом не создаёт дубликат. После завершения доступны результаты по сложности, разбор ошибочных попыток, повтор с теми же настройками и их редактирование.
- День засчитывается в серию за 3 разных верно решённых вопроса или первое прочтение темы и хотя бы один правильный ответ по ней. Простой просмотр страницы не считается. Если сегодня ещё нет активности, сохраняется серия по вчерашний день.
- Дни, недели и месяцы считаются в **UTC**; неделя начинается в понедельник. Локальное время пользователя пока не настраивается.
- Рейтинг доступен только добровольно участвующим пользователям с 30 разными решёнными вопросами и 3 темами **за выбранный период**. Сортировка: mastery по практике периода, затем XP периода, затем стабильный ID; Practice GPA — монотонная функция mastery. Username и фото удаляются из публичной проекции на сервере, если они скрыты.
- Достижения вычисляются по активности: первое задание, 3 дня подряд, 5 прочитанных тем, 30 разных решений.

## Незавершённые сессии

В начале страницы `/practice` показаны незавершённые сессии с датой, режимом, количеством выполненных заданий и отметкой блокировки Tutor. «Показать ещё» открывает более старые записи; ограничения тремя последними больше нет. «Продолжить» возвращает в ту же сессию с сохранёнными ответами.

«Завершить досрочно» доступно в списке и на странице сессии. Требуется подтверждение: закрытую сессию нельзя возобновить, но можно начать новую. Уже выполненные задания сохраняют результаты; остальные не становятся ошибками или завершёнными заданиями и не дают XP/mastery/GPA. Настоящие ранее отправленные неверные попытки остаются в разборе ошибок. При закрытии экзамена результаты уже данных ответов становятся доступны. Повторный запрос безопасен; новые ответы и подсказки из старой вкладки не меняют закрытую сессию.

Если Tutor заблокирован, уведомление указывает конкретную незавершённую сессию и даёт ссылки для продолжения или управления всем списком. Если блокирующих сессий несколько, нужно завершить каждую. Это снимает ограничение практики, но не заменяет настройку AI credentials.

## Добавление материалов

1. При необходимости добавь предмет и модули в `content/subjects.json`.
2. Добавь `content/lessons/<subject-id>/<topic-id>.mdx`. В начале укажи строго JSON-объект между строками `---` по образцу соседнего файла: `id`, `title`, `english`, `subject`, `module`, `order`, `difficulty`, `estimatedMinutes`, `prerequisites`, `keywords`, `quizAnswer`. Завершающие запятые в этом объекте недопустимы; автоформатирование MDX может их добавить. `module` должен совпадать с названием в `subjects.json`.
3. Добавь разделы `## Что это?` и `## Разберём на примере`; для ключевых тем также используй интуицию, формальное определение, обоснование, пример уровня университета, пример-ловушку, связи и типичные ошибки. Поддерживаются Markdown, формулы `$…$`/`$$…$$` и блоки кода с языком, например `c`. JSX/JavaScript в уроках не исполняется. Раздел `## Формула и её смысл` с блочной формулой автоматически попадает в Книгу формул.
4. Добавь `content/questions/<subject-id>/<topic-id>.json` с хотя бы одним заданием: стабильные уникальные `id`, `topicId`, тип, сложность, условие, ответ, полное решение, ровно три последовательные подсказки и опциональные `feedback` для типичных неверных ответов. Используй соседний файл как шаблон.
5. Запусти `npm run db:seed`, `npm test` и `npm run test:integration`.

Файлы проверяются при seed; страницы работают через слой `content-service` и БД, а не читают файлы напрямую. Прежние результаты пользователя сохраняются при обновлении контента. Не меняй смысл существующего question ID после появления результатов: публикуй новый ID. Поле version предусмотрено, но редактора и снимков прежних версий ещё нет.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run db:generate
npm run db:migrate
npx prisma validate
npm run build
```

Интеграционные тесты используют `.env`, создают временных пользователей и отдельные тестовые предметы/темы для Tutor retrieval, удаляют свои записи после выполнения и не сбрасывают базу. Нужны запущенная PostgreSQL и загруженный seed. Они проверяют конкурентные отправки, межсессионную защиту XP, права на задания, подсказки, закрытие вопроса, уникальность daily, ограничения БД, приватность рейтинга, необоснованные оценки/слабые темы, обучающий feedback, скрытие результатов экзамена, Tutor ownership/quotas/leases и актуальность course index.

Для браузерных тестов запусти `npm run dev` в отдельном терминале, затем:

```sh
npm run test:e2e
```

Конфигурация использует установленный Google Chrome. Если его нет, установи Chrome или измени `launchOptions.channel` и установи Chromium через `npx playwright install chromium`. E2E выполняет локальный вход, изучение темы, практику всех вопросов проекции, сохранение настроек, поиск, тёмную тему и мобильную проверку переполнения. Он добавляет результаты **в локальный демо-аккаунт**. Снимки находятся в `test-results/`.

## Production

```sh
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run build
npm start
```

Нужны HTTPS, рабочая PostgreSQL и Telegram credentials. `next start` запускается в production; локальный dev-вход запрещён независимо от `DEV_AUTH`. Секреты должны поступать из окружения. Seed следует запускать контролируемо при публикации материалов. Для Tutor дополнительно настрой AI env и обнови индекс по инструкции выше; без них основная практика продолжает работать. Миграция Tutor должна быть применена перед запуском нового кода. Внешние шрифты не нужны.

## Ограничения первой версии

- Это стартовый набор материалов, а не полный учебник. Углублены одиннадцать ключевых тем из пяти предметов; 45 из 56 тем пока имеют по одному заданию, хотя общий банк вырос до 92 вопросов. Высокий mastery и статус PRACTICED требуют нескольких разных задач. Расширение проверенного банка — главный следующий шаг.
- Краткие ответы и исправления C проверяются по заданным вариантам; нет символического решателя, свободной проверки доказательств или исполнения кода.
- Настоящий Telegram-вход проверяется владельцем с собственным ботом; credentials не включены в проект.
- Нет редактора контента, часового пояса в профиле, сброса локального прогресса, пагинации больших историй и отдельного глобального rate limiter. Есть лимит создания 30 сессий в час на пользователя; до публичного масштабирования нужны мониторинг, резервное копирование и ограничения на уровне ingress.
- Рейтинг вычисляется по данным на чтении; для большого числа студентов потребуются агрегаты и пагинация.
- Tutor V1 имеет ограничения, описанные выше; live AI и преподавательская оценка не заменяются автотестами. Безопасная песочница C отложена.
