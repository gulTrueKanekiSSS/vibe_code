## Что это?

Арифметика указателей позволяет двигаться между элементами одного массива. Прибавление $1$ к `int *` означает переход к следующему `int`, а не к следующему байту.

## Интуиция

Указатель — адрес ячейки в последовательности однотипных элементов. Шаг определяется типом: `p + k` указывает на элемент с индексом, увеличенным на `k`.

## Formal Definition

Если `p` указывает на элемент `a[i]` массива из `n` элементов, выражение `p + k` допустимо, когда `0 <= i + k <= n`. Результат при `i + k == n` — указатель one-past-the-end; его можно сравнивать и вычитать с указателями того же массива, но нельзя разыменовывать. Вычитание двух указателей внутри одного массива даёт разность индексов типа `ptrdiff_t`.

## Зачем это нужно?

Так обходят массивы, строят итераторы и работают с буферами. Понимание границ помогает обнаружить выход за массив и ошибки памяти.

## Английские термины

Pointer arithmetic — Арифметика указателей

one-past-the-end — позиция сразу после массива; pointer difference — разность указателей; `sizeof` — размер объекта в байтах.

## Правило и его смысл

Для `T *p` выражение `p + k` смещается на `k * sizeof(T)` байт в памяти. Это объясняет адреса, но в C стандарт гарантирует корректность арифметики только в пределах одного массива (плюс one-past). Указатели на одиночные объекты для этой цели ведут себя как массив из одного элемента.

## Почему правило работает?

Элементы массива хранятся подряд. Если первый элемент начинается по адресу `A`, то следующий объект `T` начинается после `sizeof(T)` байт. Оператор `+` для `T *` уже учитывает размер типа; вручную умножать индекс на `sizeof(T)` в выражении `p + k` не нужно.

## Разберём на примере

```c
int a[] = {10, 20, 30};
int *p = a;
// p + 2 указывает на a[2]; *(p + 2) равно 30
```

`p` указывает на `a[0]`; два шага приводят к `a[2]`. Выражения `p[2]`, `*(p + 2)` и `a[2]` здесь эквивалентны.

## Пример уровня университета

Сначала изобразим массив без предположений о конкретных адресах:

```text
индекс       0       1       2
          ┌───────┬───────┬───────┐
значение  │  10   │  20   │  30   │
          └───────┴───────┴───────┘
              ▲
              p
```

Для **двух отдельных запусков** с таким начальным состоянием:

- `++*p` разбирается как `++(*p)`: меняет первый элемент с 10 на 11, возвращает 11, оставляет `p` на индексе 0.
- `*++p` разбирается как `*(++p)`: переводит `p` на индекс 1, читает 20, оставляет массив неизменным.
- `*p++` разбирается как `*(p++)`: читает старый первый элемент 10, затем `p` указывает на индекс 1.

У префиксных `++` и `*` группировка справа налево; постфиксный `++` имеет более высокий приоритет. Выражение говорит, **что именно** меняется: указатель или объект по адресу.

## Расстояние между элементами

```c
#include <stddef.h>
int a[] = {4, 8, 12, 16};
int *first = &a[1];
int *last = &a[3];
ptrdiff_t distance = last - first; // 2 элемента, не 2 байта
```

Вычитание возвращает число элементов между адресами. Для вывода `ptrdiff_t` через `printf` используют формат `%td`.

## Пример-ловушка

```c
int a[3] = {1, 2, 3};
int *end = a + 3;  // допустимо
// *end;           // неопределённое поведение: элемента a[3] нет
```

`end - a` равно `3`, но читать `*end` нельзя. Выражение `a + 4` уже выходит за допустимую область арифметики указателей.

## Частая ошибка

Не путай шаг по элементам с шагом по байтам и не разыменовывай one-past. Нельзя вычитать указатели на разные массивы: арифметика между несвязанными объектами не определяет расстояние в элементах.

## Связи с другими темами

Индексация массива `a[i]` эквивалентна `*(a + i)`. Границы массива связывают арифметику указателей с безопасностью памяти и работой циклов.
