## Что это?

Struct объединяет одновременно существующие поля, union позволяет разным представлениям занимать общую область памяти, enum задаёт именованные целочисленные константы. Эти средства решают разные задачи и не заменяют друг друга.

## Интуиция

Struct — карточка со всеми заполненными графами. Union — один участок памяти, которому дают несколько названий и типов. Чтобы знать, какое представление сейчас используется, рядом часто хранят enum-метку.

## Formal Definition

Члены struct расположены в порядке объявления, но между ними и в конце возможно padding. Union достаточно велик для любого своего члена; его размер также учитывает выравнивание. Размеры нельзя получать простым сложением без условий о реализации.

## Английские термины

Member — поле; padding — выравнивающие промежутки; tagged union — объединение с меткой; bit field — битовое поле; mask — маска; representation — представление.

## Правило и его смысл

~~~c
enum Kind { INTEGER, REAL };
struct Value {
    enum Kind kind;
    union { int integer; double real; } data;
};
~~~

По kind выбирай смысл данных. Запись одного члена union не сохраняет независимое старое значение другого. Чтение иного представления требует анализа правил C и может не дать переносимого результата.

## Почему это работает?

Struct хранит отдельные поля, поэтому присваивание одной структуры другой копирует значения всех членов, включая встроенный массив. Указатель внутри структуры копирует адрес, а не объект по адресу. Union использует общую память; независимых мест для двух значений нет.

## Разберём на примере

~~~c
struct Point { int x, y; };
struct Point a = {2, 5};
struct Point b = a;
b.x = 9;
~~~

У a.x остаётся 2, у b.x — 9. Но если оба объекта содержали бы один и тот же int *p, изменение *b.p было бы видно через a.p.

## Пример уровня университета

Пусть формат задаёт: mode занимает биты 0–2, ready — бит 3. Для unsigned word:

~~~c
unsigned word = (mode & 7u) | ((ready & 1u) << 3);
unsigned restored_mode = word & 7u;
unsigned restored_ready = (word >> 3) & 1u;
~~~

При mode=5, ready=1 получаем 13. Формат задаётся явно; он не предполагает конкретное размещение C bit fields в памяти.

## Пример-ловушка

~~~c
struct Flags { unsigned mode : 3; unsigned ready : 1; };
~~~

Нельзя заключить, что sizeof(struct Flags)==1 или что mode всегда занимает младшие три бита. Порядок размещения и единица хранения зависят от реализации. Для протокола лучше явно определить целочисленный формат.

## Частая ошибка

Сортировать массив структур, меняя местами только поле score: так имя и балл разъедутся. Переставляй целые записи. При равных ключах заранее определи правило сравнения и необходимость стабильности.

## Зачем это нужно?

Структуры моделируют записи файла и элементы таблицы. Enum делает состояние понятным в switch. Маски и сдвиги позволяют хранить несколько небольших значений в одном беззнаковом слове.

## Связи с другими темами

[Битовые операции](/topics/c-bitwise) связаны с [булевой логикой схем](/topics/boolean). Порядок байтов — отдельный вопрос от порядка битовых полей. Байты любого объекта можно рассматривать через unsigned char, но их конкретный порядок без условий не угадывают.

## Как говорит преподаватель

“Sort an array of structures by enum category, then by score.” Укажи порядок категорий и правило равенства ключей, затем сохраняй целостность записей.

## Краткий итог

Struct хранит вместе, union разделяет память, enum называет состояния. Отделяй значение от представления и переносимый формат от особенностей компилятора.
